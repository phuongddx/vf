# vf Codegen (Hybrid) + Full Render — Design Spec (Sub-project B2)

- **Date:** 2026-10-31
- **Status:** draft (awaiting owner review)
- **Repo state at write time:** main = 5acd309, v0.2.0 released (TLS + LLM spec generation), 69/69 tests

## Problem

vf's Remotion engine writes a static scaffold and prints the render command — it
cannot render a real video. The spec stage produces LLM JSON, but nothing turns
that into React code, and `npx remotion render` has never actually run. The
"LLM writes video code" differentiator does not exist yet.

## Goals

1. Scaffold becomes a REAL working Remotion project that always renders any
   `video.spec.json` (guaranteed baseline via template Player).
2. Hybrid codegen: LLM generates custom scene components for scenes marked
   `custom`, validated, with template fallback.
3. Full render execution: `vf make` runs `npm install` → `npx remotion render`
   → ffmpeg post, producing real mp4 output.
4. **Demo video deliverable (owner request, 2026-10-31 09:16):** a real video
   generated by vf itself, committed to the repo and embedded in the README on
   GitHub.
5. Invariant preserved: `vf make` never fails because of codegen/render
   problems — always degrade + bilingual warning.

## Context & constraints

- Gateway container: node v24 + npm OK; **ffmpeg MISSING** (doctor). Demo video
  uses Remotion's direct mp4 output (draft.mp4 is a complete video; post stage
  remux is optional for the demo).
- First real render downloads Remotion npm packages (~100 MB+) and Chrome
  Headless Shell (~150 MB) into the workspace — disk-checked before starting.
- LLM spec/codegen reuse B machinery: built-in profiles, RetryingClient,
  extract_json, validate-retry-fallback, usage/cost lines, bilingual i18n.
- Exact Remotion dependency versions + entry conventions verified against
  Remotion docs during plan writing.

## Design

### 1. Real Remotion scaffold (`src/engine/scaffold.rs` rewrite)

- `package.json` — deps `@remotion/cli`, `react`, `react-dom` (+ `typescript`
  dev dep for validation), versions pinned at plan time.
- `src/index.tsx` — `registerRoot`, Root registers Composition `vf-main` with
  fps/dimensions from `video.spec.json` (9:16 → 1080×1920, 16:9 → 1920×1080,
  1:1 → 1080×1080).
- `src/Player.tsx` — data-driven: loads spec, maps each scene to either
  `Custom_s{id}` (if scene.custom AND file exists) or `SceneView`.
- `src/SceneView.tsx` — template rendering: text elements (font from style,
  palette colors), image elements (staticFile), narration captions, basic
  transitions; timing from `scene.duration` × fps.
- `src/scenes/` — empty dir; LLM components land here as `Custom_s{id}.tsx`.
- `remotion.config.ts` — minimal config (entry point).

### 2. Spec schema extension (`src/ir.rs`)

- `Scene.custom: bool` with `#[serde(default)]` — old specs parse unchanged.
- Spec-stage LLM prompt updated: mark `custom: true` ONLY for scenes needing
  effects the template can't express; default false.

### 3. Codegen stage (`src/cmd/make.rs`, after spec stage)

- Resolve `routing.codegen` → provider → key; offline → skip with warning
  (whole video renders from template).
- For each custom scene: prompt (scene JSON + style + palette + component
  contract: default-export React component receiving `{scene}` props) →
  `RetryingClient` → `src/scenes/Custom_s{id}.tsx`.
- **Validation:** if node available → run `npx tsc --noEmit` in scaffold dir
  (via Executor); on failure → 1 retry with compiler error attached → still
  failing → delete file, scene falls back to SceneView + warning. No node →
  light check (`export default` present) + warning that tsc was skipped.
- Codegen usage/cost accumulates with spec usage in the final report line.

### 4. Full render path (`src/engine/remotion.rs` via Executor)

Toolchain pre-check (node, npx, ffmpeg): any missing → skip real render, print
the exact manual commands (`npm install && npx remotion render vf-main
draft.mp4`), keep all artifacts, exit 0.

1. `npm install --no-audit --no-fund` — skipped when `node_modules` exists AND
   a hash of package.json matches the last install (`.vf-install-hash`).
2. `npx remotion render vf-main draft.mp4` — first run downloads Chrome
   Headless Shell (~150 MB; bilingual note printed before).
3. Post stage unchanged (ffmpeg remux; dry-run engine keeps fs::copy).
4. `VF_ENGINE=dry-run` unchanged for CI/tests/hostile environments.

### 5. i18n additions

`codegen_offline_skip`, `codegen_fallback(scene, reason)`, `npm_install_running`,
`render_running`, `render_skipped_manual(cmd)`, `chrome_first_run_note`,
`codegen_usage_line` — all VI/EN.

### 6. Demo video deliverable (Q3)

1. After B2 lands: run `vf make "<demo idea>" --template launch` on the gateway
   with `VF_ENGINE=remotion`.
   - With `ZAI_CODING_API_KEY` in env (owner adds like GH_TOKEN) → full-LLM
     demo (spec + codegen + render). Without → offline template render (still a
     real vf-rendered video; noted in demo caption).
2. Output kept short (10–15 s, ≤5 MB) → committed as `docs/demo.mp4`.
3. README: embed via HTML `<video src="docs/demo.mp4">` (GitHub renders
   committed videos in markdown); fallback if unsupported: animated GIF preview
   + link to the mp4 raw URL / release asset.

### 7. Testing

- Unit: `Scene.custom` parse/round-trip; codegen prompt builder; install-hash
  skip logic; fallback-file deletion logic.
- Integration (wiremock LLM + Executor mocks): full make flow with mocked
  codegen returning valid TSX → scaffold contains `Custom_s*.tsx`, npm/npx/tsc
  command shapes asserted via MockExecutor; tsc-fail → fallback + warning;
  offline codegen → template only; missing node → render_skipped + manual cmd.
- No real Chrome render in CI.

## Error handling summary

Never crash: codegen failures delete custom files and fall back to template
scenes; render failures print manual commands; every degradation is a bilingual
warning line; artifacts always preserved.

## Non-goals (explicit)

HyperFrames engine, TTS, premium tier, streaming, cross-scene LLM state,
codegen of non-scene project files (Player/index stay template-owned).
